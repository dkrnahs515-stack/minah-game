# Pixel World 10배 월드·포탈 설계

- 작성일: 2026-08-05
- 대상 저장소: `dkrnahs515-stack/pixel_world`
- 대상 브랜치: `feature/world-10x-portals`

## 1. 목표

현재 단일 월드의 플레이 가능 면적을 정확히 10배로 확장하고, 중앙 마을·화산·숲·해안의 네 독립 지역을 포탈로 연결한다. 중앙 마을은 몬스터가 존재하거나 진입할 수 없는 안전지대로 유지한다. 외부 세 지역에는 지형별 몬스터가 결정론적 위치에 생성된다. 기존 Firebase 익명 인증과 실시간 플레이어 동기화, 닉네임 입장, 나가기, 방향키 이동, Ctrl/Q 전투와 부활 기능은 보존한다.

## 2. 현재 상태 점검

- 현재 월드 크기: `2,880 × 1,800px`
- 현재 월드 면적: `5,184,000px²`
- 현재 구조: 사막 문명·태고의 숲·빙결 왕국·중앙 초원이 하나의 오프스크린 캔버스에 렌더링됨
- 현재 적: 중앙 초원 좌표에 슬라임 3마리가 각 브라우저에서 로컬로 생성됨
- 현재 네트워크: `rooms/public/players/{uid}`에 위치, 방향, 이동 상태, 색상, 닉네임을 최대 초당 20회 기록함
- 현재 입장/퇴장: 닉네임 검증 후 익명 로그인하며, 나가기 또는 페이지 종료 시 플레이어 경로를 삭제함

## 3. 확정된 월드 크기

| 지역 | mapId | 크기 | 면적 | 기존 대비 |
|---|---|---:|---:|---:|
| 중앙 마을 | `village` | `2,880 × 1,800` | 5,184,000px² | 1배 |
| 활화산 | `volcano` | `4,320 × 3,600` | 15,552,000px² | 3배 |
| 태고의 숲 | `forest` | `4,320 × 3,600` | 15,552,000px² | 3배 |
| 해안가 | `coast` | `4,320 × 3,600` | 15,552,000px² | 3배 |
| 합계 | 4개 지역 | - | 51,840,000px² | 정확히 10배 |

각 지역은 별도 오프스크린 캔버스로 생성하며 활성 지역 하나만 메모리에 유지한다. 이 방식은 전체 51,840,000px²를 동시에 캔버스로 생성하는 약 207MB 이상의 픽셀 버퍼 사용을 피한다.

## 4. 아키텍처와 파일 경계

### `src/world-data.js`

DOM과 무관한 순수 데이터 모듈이다. 네 지역의 `id`, 표시 이름, 크기, 플레이어 시작점, 포탈, 장애물, 몬스터 생성 목록을 소유한다.

다음 인터페이스를 제공한다.

- `WORLD_IDS: readonly string[]`
- `WORLD_DEFINITIONS: Readonly<Record<WorldId, WorldDefinition>>`
- `getWorldDefinition(mapId): WorldDefinition`
- `getTotalWorldArea(): number`
- `getPortalDestination(mapId, portalId): PortalDestination | null`
- `isSafeWorld(mapId): boolean`

잘못된 `mapId`는 `village`로 정규화한다.

### `src/world.js`

현재 지역의 정적 레이어 생성, 지형 그리기, 장애물·경계 충돌, 포탈 영역 조회를 담당한다.

다음 인터페이스를 제공한다.

- `createWorldLayer(mapId): HTMLCanvasElement`
- `isWorldPositionBlocked(mapId, x, y, radius): boolean`
- `findActivePortal(mapId, x, y, radius): Portal | null`
- `getBiome(mapId, x, y): string`

지역별 렌더 함수는 같은 모듈 내부에서 분리하되 호출자는 `mapId`만 전달한다.

### `src/enemies.js`

기존 슬라임 상태 머신을 일반화한다. 적 객체는 `kind`, 표시 이름, 색상, HP, 속도, 접촉 피해, 추적 거리와 귀환 거리를 가진다.

- `createEnemies(mapId): Enemy[]`는 중앙 마을에서 항상 빈 배열을 반환한다.
- 활화산: 화염 슬라임
- 태고의 숲: 숲 슬라임과 멧돼지
- 해안가: 해안 게와 물방울 슬라임
- 모든 적은 해당 지역 경계와 장애물 충돌을 사용하고 포탈 전환 로직에는 접근하지 않는다.

적 상태는 기존 방식대로 클라이언트 로컬로 유지한다. 몬스터 서버 권위 동기화는 이번 범위에 포함하지 않는다.

### `src/network-state.js`

Firebase에 의존하지 않는 순수 변환 모듈이다.

- `serializePlayerState(player, mapId): PlayerSnapshot`
- `normalizeMapId(value): WorldId`
- `filterPlayersForMap(rawPlayers, ownUid, mapId): Map<string, PlayerSnapshot>`

기존 레코드에 `mapId`가 없으면 `village`로 간주한다.

### `src/network.js`

기존 익명 로그인과 연결 수명주기를 보존한다. `publish`에 `mapId`를 추가하고, 수신 시 같은 `mapId`의 플레이어만 전달한다. `onDisconnect().remove()`, 명시적 `remove(playerRef)`, 중복 앱 초기화 방지 로직은 유지한다.

### `src/game.js`

활성 `mapId`, 포탈 전환 잠금, 지역 레이어 교체, 지역별 적 초기화를 통합한다. 전환 시 플레이어 현재/이전 좌표와 카메라 현재/이전 좌표를 함께 재설정해 한 프레임 동안 이전 지역에서 새 지역으로 보간되는 현상을 막는다.

## 5. 지역 구성

### 중앙 마을

중앙 광장을 기준으로 다음 공간을 구분한다.

- 북쪽: 마을 회관과 촌장 위치
- 서쪽: 농장, 밭, 헛간과 농부 위치
- 동쪽: 상점·대장간과 상인·대장장이 위치
- 남쪽: 무역소, 짐마차와 해안 포탈
- 북서쪽: 숲 포탈
- 북동쪽: 화산 포탈

NPC는 이번 범위에서 정적인 픽셀 캐릭터와 이름표로 표시한다. 대화·퀘스트·상점 거래 시스템은 포함하지 않는다.

마을 정의의 `enemySpawns`는 빈 배열이다. 적은 지역 간 포탈을 사용할 수 없으므로 외부 적이 마을에 진입할 실행 경로가 존재하지 않는다.

### 활화산

검은 현무암, 용암 강, 분화구, 열기 아지랑이, 잿빛 지면과 안전 통로를 배치한다. 용암과 분화구는 충돌 지형이다. 화염 슬라임은 안전 통로 밖의 여러 구역에 배치한다.

### 태고의 숲

울창한 수목 군락, 거대한 고목, 숲길, 연못과 목교를 배치한다. 나무줄기·연못은 충돌 지형이고 길과 목교는 통과 가능하다. 숲 슬라임과 멧돼지는 서로 다른 구역에 배치한다.

### 해안가

모래사장, 절벽, 얕은 물, 부두, 난파선과 등대를 배치한다. 깊은 물·절벽·난파선은 충돌 지형이다. 해안 게와 물방울 슬라임은 해변과 얕은 물 경계에 배치한다.

## 6. 포탈 흐름

1. 플레이어가 포탈 중심 영역에 들어간다.
2. `findActivePortal`이 포탈을 반환한다.
3. 전환 잠금이 0이면 입력을 잠그고 화면 페이드를 시작한다.
4. 대상 `mapId`와 도착 포탈 좌표를 검증한다.
5. 활성 월드 레이어를 새 지역으로 교체한다.
6. 해당 지역의 몬스터를 생성한다.
7. 플레이어와 카메라의 현재/이전 좌표를 도착 좌표로 설정한다.
8. 미니맵 기반 레이어와 지역명을 갱신한다.
9. 화면을 복구하고 입력을 다시 허용한다.
10. 1초의 포탈 재사용 잠금을 적용해 즉시 역이동을 막는다.

대상 지역이나 도착 좌표가 유효하지 않으면 전환하지 않고 현재 지역에 남으며 `포탈이 불안정합니다.` 메시지를 표시한다.

## 7. 전투·사망·안전지대

- 공격 키, 공격 피해, MP 비용, 재사용 대기시간은 변경하지 않는다.
- `createEnemies("village")`는 항상 빈 배열이다.
- 공격은 현재 지역의 적에게만 적용된다.
- 외부 지역의 적은 지역별 충돌 함수로만 이동한다.
- 플레이어가 사망하면 기존 1.2초 부활 연출 후 `village`의 중앙 광장 시작점에서 HP·MP를 모두 회복한다.
- 부활 시 지역 레이어, 적 목록, 미니맵과 Firebase `mapId`가 중앙 마을 상태로 함께 전환된다.

## 8. Firebase 데이터와 보안 규칙

플레이어 레코드는 기존 필드에 `mapId`를 추가한다.

```json
{
  "x": 1440,
  "y": 1110,
  "dir": "down",
  "moving": false,
  "color": "#4f8e5b",
  "name": "모험가",
  "mapId": "village",
  "updatedAt": 0
}
```

규칙은 `mapId`를 `village|volcano|forest|coast`로 제한한다. 중앙 마을은 `x <= 2880`, `y <= 1800`, 외부 지역은 `x <= 4320`, `y <= 3600`을 검증한다. 읽기 권한과 자기 UID만 쓰는 권한은 유지한다.

## 9. UI와 미니맵

- 플레이어 패널의 지역명을 활성 지역 표시 이름으로 갱신한다.
- 미니맵은 활성 지역 하나만 표시한다.
- 포탈은 목적지 이름과 색상으로 구분한다.
- 포탈 전환 중 비상호작용 페이드 레이어와 목적지 이름을 표시한다.
- 중앙 마을에서는 안전지대 안내를, 외부 지역에서는 해당 지역 이름과 몬스터 경고를 짧게 표시한다.
- 기존 HUD, 닉네임 입장 화면과 나가기 확인창의 구조는 유지한다.

## 10. 오류 처리와 호환성

- 알 수 없는 `mapId`: 중앙 마을로 정규화
- 대상 없는 포탈: 전환 취소와 안내 메시지
- 좌표가 지역 범위를 벗어난 원격 플레이어: 표시하지 않음
- `mapId`가 없는 과거 Firebase 데이터: 중앙 마을 플레이어로 취급
- Firebase 연결 실패: 기존 오프라인 모드 유지
- 게임 나가기: 어떤 지역에서도 네트워크 데이터를 삭제하고 입장 화면으로 복귀
- 재입장: 중앙 마을에서 새 세션 시작
- 화면 크기 변경: 현재 지역 크기로 카메라를 다시 제한

## 11. 테스트 전략

Node 내장 테스트 러너를 사용하고 의존성이나 번들러를 추가하지 않는다.

### 순수 단위 테스트

- 네 지역 합계가 `51,840,000px²`이고 현재 면적의 정확히 10배인지 확인
- 중앙 마을과 외부 지역 크기 확인
- 모든 포탈 대상과 도착 좌표가 유효한지 확인
- 중앙 마을의 적 생성 수가 0인지 확인
- 외부 지역의 지형별 적 종류와 생성 수 확인
- 지역 경계와 대표 장애물 충돌 확인
- `mapId` 직렬화, 이전 데이터 정규화, 같은 지역 플레이어 필터 확인
- 기존 공격, 입력, 피해, 부활 테스트 회귀 확인

### 정적 검증

모든 `src/*.js` 파일에 `node --check`를 실행한다. HTML의 필수 요소 ID와 Firebase 규칙 JSON 구문도 검사한다.

### 브라우저 플레이테스트

- 닉네임 입장과 오프라인/온라인 시작
- 중앙 마을에 몬스터가 없는지 확인
- 마을 건물과 NPC 표식의 가독성 확인
- 세 포탈과 세 귀환 포탈을 각각 왕복
- 포탈 위에서 연속 재전환이 발생하지 않는지 확인
- 각 외부 지역 몬스터 추적·공격·피격·처치 확인
- 외부 지역에서 사망한 뒤 중앙 마을 부활 확인
- 나가기 후 플레이어 정리와 재입장 확인
- 데스크톱과 축소 뷰포트에서 HUD·미니맵 겹침 확인
- 대표 화면을 캡처하여 지역 구분과 포탈 가독성을 검토
