# 현자 아렌 첫 퀘스트 설계

## 목표

중앙 마을의 현자 아렌과 `F`로 대화하고, 외부 지역의 슬라임 3마리를 처치한 뒤 아렌에게 보고하여 EXP 15를 한 번만 획득하는 첫 번째 완성형 퀘스트 흐름을 구현한다. 퀘스트 상태와 누적 EXP는 별도 계정 서버 없이 현재 브라우저에 닉네임별로 저장한다.

## 범위

### 포함

- 중앙 마을에 상호작용 가능한 현자 아렌 배치
- 아렌 근처에서 `F 대화하기` 안내 표시
- 대화창 열기, 퀘스트 수락, 진행 상황 안내, 완료 보고
- 화염 슬라임, 숲 슬라임, 물방울 슬라임 처치를 동일한 슬라임 처치로 집계
- 수락 전 처치 제외, 최대 3마리까지만 집계
- 완료 보고 시 EXP 15를 정확히 한 번 지급
- 현재 퀘스트와 진행도 `0/3`~`3/3` HUD 표시
- 누적 EXP HUD 표시
- 닉네임별 `localStorage` 저장과 재입장 복원
- 손상되거나 오래된 저장 데이터의 안전한 초기화
- 키보드와 화면 버튼 양쪽의 대화 조작
- 단위 테스트, 정적 UI 스모크 테스트, 기존 57개 테스트 회귀 검증

### 제외

- 새로운 중앙 초원 지역
- 몬스터 드롭, 골드, 인벤토리, 상점
- 레벨업과 능력치 증가
- 여러 퀘스트를 동시에 추적하는 퀘스트 목록
- Firebase 퀘스트 동기화 및 다른 기기 저장
- 여러 플레이어가 공유하는 몬스터·퀘스트 진행도
- 모바일 전용 가상 이동 버튼

## 선택한 접근

현재 월드와 몬스터를 재사용하는 최소 수직 기능을 선택한다. 새 `meadow` 지역을 추가하면 월드 정의, 포탈, Firebase `mapId` 규칙과 배포까지 동시에 변경해야 하므로 첫 퀘스트의 핵심인 대화·처치 집계·보상·저장 검증 범위를 흐린다.

퀘스트 대상은 `fire-slime`, `forest-slime`, `water-slime` 세 종류로 한정한다. 멧돼지와 해안 게는 집계하지 않는다. 이후 중앙 초원을 추가하면 `meadow-slime`을 동일한 대상 목록에 넣을 수 있다.

## 사용자 흐름

1. 닉네임을 입력하고 중앙 마을에 입장한다.
2. 현자 아렌에게 80px 이내로 접근하면 `F 대화하기` 안내가 나타난다.
3. `F`를 누르면 이동과 공격이 멈추고 대화창이 열린다.
4. 아렌의 설명을 읽고 `퀘스트 수락`을 누른다.
5. 외부 지역에서 슬라임을 처치할 때마다 퀘스트 추적기가 `1/3`, `2/3`, `3/3`으로 갱신된다.
6. 3마리 처치 후 아렌과 다시 대화하면 `완료 보고` 버튼이 나타난다.
7. 보고 시 EXP 15가 지급되고 퀘스트는 완료 상태가 된다.
8. 같은 브라우저에서 같은 닉네임으로 다시 입장하면 퀘스트 상태와 EXP가 복원된다.

## 아키텍처

### NPC 데이터와 상호작용

`src/npc-data.js`는 NPC의 ID, 이름, 월드, 좌표, 상호작용 반경만 제공한다. `src/npcs.js`는 가까운 NPC 탐색과 캔버스 렌더링을 담당한다. 정적 배경에 그려진 기존 촌장은 제거하고 동일 위치에 동적 아렌 엔티티를 표시한다.

```js
{
  id: "aren",
  name: "현자 아렌",
  mapId: "village",
  x: 1440,
  y: 520,
  interactionRadius: 80,
  coatColor: "#6f5bd3"
}
```

### 퀘스트 상태

`src/quest-state.js`는 DOM이나 저장소를 알지 못하는 순수 상태 전이 모듈이다.

```text
AVAILABLE -> ACTIVE -> READY_TO_REPORT -> COMPLETED
```

- `acceptQuest(state)`는 `AVAILABLE`에서만 `ACTIVE`로 전환한다.
- `recordEnemyKill(state, enemyKind)`는 `ACTIVE`일 때 승인된 슬라임만 집계한다.
- 세 번째 유효 처치에서 `READY_TO_REPORT`로 전환한다.
- `completeQuest(state)`는 `READY_TO_REPORT`에서만 `COMPLETED`와 EXP 15 보상을 반환한다.
- 완료 상태에서 반복 호출해도 보상은 0이다.

### 브라우저 저장

`src/progress-storage.js`는 저장소를 주입받아 테스트할 수 있도록 설계한다. 저장 키는 정규화한 닉네임을 포함한다.

```text
pixel-world.progress.v1:<nickname>
```

저장 데이터는 다음 최소 구조만 가진다.

```js
{
  version: 1,
  exp: 0,
  quests: {
    adventureStart: {
      status: "available",
      progress: 0
    }
  }
}
```

JSON 파싱 실패, 버전 불일치, 음수 EXP, 알 수 없는 상태, 범위를 벗어난 진행도는 기본 상태로 초기화한다. 게임 입장 시 한 번 불러오고, 퀘스트 수락·유효 처치·완료 보고 직후 저장한다.

### 대화 UI

`src/dialogue-controller.js`는 대화창 표시와 버튼 이벤트만 담당한다. 게임은 현재 퀘스트 상태에 따라 아렌의 대화 모델을 전달한다.

| 상태 | 아렌의 안내 | 주요 버튼 |
|---|---|---|
| `available` | 외부 지역의 슬라임을 정리해 달라고 요청 | 퀘스트 수락 |
| `active` | 현재 처치 수 안내 | 대화 마치기 |
| `ready_to_report` | 임무 완료 확인 | 완료 보고 |
| `completed` | 모험가의 성장을 격려 | 대화 마치기 |

대화창이 열리면 이동·공격·포탈 진입을 차단하고 입력 키를 비운다. `F`, `Esc`, 닫기 버튼으로 대화를 닫을 수 있다. 채팅 입력 중에는 NPC 대화를 열지 않는다.

### 게임 통합

`src/game.js`는 다음 조정만 담당한다.

- 입장 시 닉네임별 진행 데이터 로드
- 현재 지역의 NPC 생성과 가까운 NPC 탐색
- `F` 입력을 대화 열기·닫기에 연결
- 몬스터 처치 결과가 `killed: true`일 때 퀘스트 모듈에 `enemy.kind` 전달
- 수락·처치·보고 이후 진행 데이터 저장
- EXP와 퀘스트 HUD 갱신

몬스터 AI, 공격 판정, Firebase 플레이어·채팅 동기화는 변경하지 않는다.

## 오류 및 경계 처리

- NPC가 범위 밖이면 `F` 입력은 아무 작업도 하지 않는다.
- 퀘스트 수락 전 슬라임 처치는 집계하지 않는다.
- 멧돼지·해안 게 처치는 집계하지 않는다.
- 죽는 중인 적을 다시 공격해도 중복 집계하지 않는다.
- 3마리를 넘겨 처치해도 진행도는 3을 넘지 않는다.
- 보고 버튼 연속 클릭에도 EXP는 한 번만 지급한다.
- `localStorage` 접근이 차단되면 게임은 기본 진행도로 계속 실행하고 화면 알림으로 저장 불가를 알린다.
- 닉네임이 다르면 같은 브라우저에서도 별도 진행 데이터를 사용한다.

## 테스트 기준

### 단위 테스트

- 올바른 상태 전이 네 단계
- 수락 전 처치 무시
- 비슬라임 처치 무시
- 유효 슬라임 3종 집계
- 진행도 상한 3
- 완료 보상 15와 중복 보상 방지
- 닉네임별 저장 분리
- 정상 저장 복원
- 손상·버전 불일치 데이터 초기화
- 가까운 아렌 탐색과 다른 지역·범위 밖 제외

### 통합·스모크 테스트

- `index.html`에 대화창, 퀘스트 추적기, EXP HUD가 존재
- `main.js`가 새 UI 요소를 게임에 전달
- 브라우저에서 입장, 아렌 접근, `F`, 수락, 슬라임 3마리 처치, 보고, EXP 15 확인
- 새로고침 후 같은 닉네임으로 EXP와 완료 상태 복원
- 다른 닉네임은 초기 상태로 시작
- 기존 이동, 공격, 포탈, 채팅, 나가기 기능 회귀 없음

## 완료 조건

- 자동화 테스트가 모두 통과한다.
- 실제 브라우저에서 첫 퀘스트 전체 흐름과 새로고침 복원을 확인한다.
- README 조작법과 첫 퀘스트 설명이 실제 동작과 일치한다.
- 구현은 별도 `agent/aren-first-quest` 브랜치와 Draft PR로 제공한다.
