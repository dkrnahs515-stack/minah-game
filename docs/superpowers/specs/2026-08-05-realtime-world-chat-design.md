# Pixel World 전체 월드 실시간 채팅 설계

## 목표

Firebase Realtime Database를 사용해 현재 접속 중인 모든 플레이어가 지역과 관계없이 대화할 수 있는 전체 월드 채팅을 추가한다. 왼쪽 아래 채팅 기록과 캐릭터 머리 위 말풍선을 함께 제공하며, 플레이어가 퇴장하거나 연결이 끊기면 해당 플레이어의 메시지를 서버에서 정리한다.

기존 닉네임 입장, 게임 나가기, 포탈 이동, 전투, Firebase 위치·지역 동기화는 그대로 유지한다.

## 확정된 사용자 경험

- 왼쪽 아래에 전체 월드 채팅 패널을 표시한다.
- 패널에는 모든 지역에서 전송된 최근 메시지를 시간순으로 최대 50개 표시한다.
- `Enter`를 누르면 채팅 입력창에 초점을 둔다.
- 입력 중 `Enter`를 누르면 메시지를 전송하고 게임 입력으로 돌아간다.
- 입력 중 `Esc`를 누르면 작성 내용을 유지하지 않고 입력을 취소한다.
- 채팅 입력창이 닫힌 상태에서만 `Esc`가 기존 게임 나가기 확인 창을 연다.
- 입력 중에는 이동과 공격 단축키가 작동하지 않는다.
- 같은 지역에 있어 화면에 렌더링되는 플레이어가 말하면 캐릭터 머리 위에 최신 메시지를 약 4초 동안 표시한다.
- 다른 지역 플레이어의 메시지는 전체 채팅 패널에만 표시한다.
- Firebase가 오프라인이면 채팅 입력을 비활성화하고 간단한 오프라인 안내를 표시한다.

## 데이터 구조

채팅은 기존 방 아래에 플레이어별 하위 트리로 저장한다.

```text
rooms/{roomId}/chat/{uid}/{messageId}
  text: string
  name: string
  mapId: "village" | "volcano" | "forest" | "coast"
  createdAt: server timestamp
```

플레이어별 하위 트리를 사용하는 이유는 `onDisconnect()`가 `chat/{uid}` 전체를 제거할 수 있기 때문이다. 각 플레이어는 서버에 최근 5개 메시지만 남기며, 클라이언트는 접속 중인 모든 플레이어의 메시지를 합쳐 시간순으로 정렬한 뒤 최근 50개만 표시한다.

닉네임과 지역 ID는 전송 당시 값을 저장한다. 닉네임은 기존 입장 검증을 다시 사용하고, 지역 ID는 기존 월드 ID 정규화 규칙을 적용한다.

## 모듈 경계

### `src/chat-state.js`

DOM과 Firebase에 의존하지 않는 순수 로직을 담당한다.

- 메시지 공백 정규화
- 최대 80자 검증
- 빈 메시지와 직전 메시지의 연속 중복 차단
- 플레이어별 메시지 트리를 평탄화하고 시간순으로 정렬
- 전체 표시 목록을 최근 50개로 제한
- 현재 지역에서 표시할 최신 말풍선 계산

### `src/chat-network.js`

Firebase 채팅 입출력만 담당한다.

- `rooms/{roomId}/chat` 실시간 구독
- 현재 사용자의 메시지 전송
- 사용자별 최근 5개 초과분 정리
- `onDisconnect(chat/{uid}).remove()` 등록
- 정상 퇴장 시 구독 해제와 사용자 채팅 하위 트리 삭제
- 연결 실패 시 게임이 계속 실행될 수 있는 오프라인 어댑터 반환

기존 `network.js`가 보유한 Firebase 앱·인증·데이터베이스 연결을 재사용할 수 있도록 연결 결과에 채팅 어댑터를 포함한다. Firebase 앱을 중복 초기화하거나 별도의 익명 계정을 만들지 않는다.

### `src/chat-controller.js`

채팅 UI와 키보드 흐름을 담당한다.

- `Enter`로 입력 시작과 전송
- `Esc`로 입력 취소
- 1초 전송 간격 적용
- 채팅 패널 렌더링과 자동 스크롤
- 새 메시지를 게임의 말풍선 상태로 전달
- 입력 중인지 게임 입력 계층에 노출

### 기존 파일 연결

- `index.html`: 채팅 기록, 상태, 단일 행 입력창 추가
- `styles.css`: 왼쪽 아래 반투명 패널과 픽셀 게임에 맞는 말풍선 스타일 추가
- `main.js`: 채팅 DOM 요소 연결 및 기존 `Esc` 처리와 우선순위 통합
- `game.js`: 채팅 입력 중 게임 키 입력 차단, 로컬·원격 캐릭터 말풍선 상태와 렌더링 추가
- `database.rules.json`: 인증된 사용자 읽기, UID 소유자만 쓰기·삭제, 필드와 길이 검증 추가
- `README.md`와 `FIREBASE_SETUP.md`: 채팅 데이터 경로와 규칙 배포 안내 추가

## 입력 및 표시 규칙

- 메시지는 앞뒤 공백을 제거하고 연속 공백을 하나로 줄인다.
- 글자 수는 유니코드 문자 기준 최대 80자다.
- 빈 메시지는 전송하지 않는다.
- 같은 사용자가 직전과 동일한 메시지를 연속으로 전송할 수 없다.
- 전송 성공 여부와 관계없이 무한 재시도를 하지 않는다.
- 전송 간격은 클라이언트 기준 1초다.
- 메시지는 `innerHTML`이 아니라 `textContent`로 렌더링해 HTML과 스크립트를 실행하지 않는다.
- 말풍선은 최대 80자의 동일한 내용을 표시하되 화면 밖으로 벗어나지 않도록 위치를 보정한다.
- 플레이어가 다른 지역으로 이동해도 전체 채팅 기록에는 메시지가 남아 있고, 말풍선은 같은 지역에서 보이는 캐릭터에만 표시한다.

## Firebase 보안 규칙

- 채팅 읽기는 인증된 사용자만 허용한다.
- 쓰기와 삭제는 경로의 `$uid`가 `auth.uid`와 같을 때만 허용한다.
- 새 메시지는 `text`, `name`, `mapId`, `createdAt` 필드를 모두 가져야 한다.
- `text`는 1~80자 문자열이어야 한다.
- `name`은 기존 플레이어 이름 제한과 일치하는 문자열이어야 한다.
- `mapId`는 네 개의 허용된 지역 ID 중 하나여야 한다.
- `createdAt`은 숫자 서버 시각이어야 한다.
- 알 수 없는 추가 필드는 허용하지 않는다.

Firebase 규칙만으로 정확한 1초 전송 간격을 강제하지는 않는다. 초기 버전은 인증, 소유권, 필드 검증을 서버 규칙으로 강제하고 전송 간격과 중복 차단은 클라이언트에서 적용한다. 강한 스팸 방어와 제재 기능은 별도 서버 검증이 필요한 후속 범위다.

## 종료와 오류 처리

- 정상 나가기 시 현재 사용자의 채팅 하위 트리를 삭제한다.
- 브라우저 종료나 네트워크 단절 시 `onDisconnect()`가 동일한 하위 트리를 삭제한다.
- 채팅 전송 실패는 게임 연결을 종료시키지 않고 채팅 패널에 짧게 알린다.
- 채팅 구독 실패 시 채팅만 오프라인으로 전환하고 이동 동기화와 싱글 플레이 동작은 유지한다.
- 서버에서 잘못된 메시지를 받으면 해당 항목만 무시한다.
- 플레이어 데이터보다 채팅 메시지가 먼저 도착하더라도 저장된 닉네임으로 채팅 패널을 표시한다.

## 검증 계획

- 메시지 정규화, 길이, 빈 값, 중복 차단 단위 테스트
- 플레이어별 중첩 데이터를 평탄화하고 최근 50개로 제한하는 단위 테스트
- 지역과 UID를 이용해 말풍선 대상을 선택하는 단위 테스트
- 채팅 입력 중 이동·공격·나가기 키가 차단되는 입력 테스트
- Firebase 직렬화 데이터와 허용 필드 테스트
- Firebase 규칙 JSON 구문 검사
- 브라우저 스모크 테스트로 채팅창 열기, 전송, 기록 표시, 말풍선, `Esc` 우선순위, 나가기 후 입장 화면 복귀 확인
- 두 브라우저 세션을 사용할 수 있는 환경에서는 서로 다른 지역 간 전체 채팅과 같은 지역 말풍선을 수동 검증

## 이번 구현에서 제외하는 범위

- 귓속말, 파티, 길드, 지역별 채널 탭
- 영구 채팅 기록과 24시간 보존
- 운영자 신고, 차단, 제재 화면
- 서버 기반 금칙어·스팸 판정
- 이미지, 링크 미리보기, 파일 첨부
- NPC 대화 시스템
