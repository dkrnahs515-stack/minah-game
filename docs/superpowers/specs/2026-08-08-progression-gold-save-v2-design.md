# 경험치·골드·저장 v2 설계

## 목표

현재 첫 퀘스트 진행 데이터에 레벨, 현재 레벨 EXP, 다음 레벨 필요 EXP, Gold, 완료 퀘스트 목록을 추가한다. 슬라임 반복 사냥과 첫 퀘스트 완료 보상을 성장 데이터에 반영하고, 닉네임별 브라우저 localStorage에 안전하게 저장한다.

이번 단계는 브라우저 저장을 사용한다. 다른 기기 간 동기화와 서버 변조 방지는 이후 Firebase 사용자별 저장 단계에서 구현한다.

## 확정 규칙

- 시작 레벨은 `1`이다.
- 현재 레벨에서 다음 레벨까지 필요한 EXP는 `level * 100`이다.
- 레벨업에 사용하고 남은 EXP는 다음 레벨로 이월한다.
- 한 번의 보상으로 여러 레벨 조건을 충족하면 연속 레벨업한다.
- 슬라임 처치 보상은 `3 EXP`와 무작위 `1~3 Gold`다.
- 첫 퀘스트 완료 보상은 `15 EXP`와 `30 Gold`다.
- 레벨업할 때마다 최대 HP는 `10`, 최대 MP는 `5` 증가한다.
- 레벨업 직후 현재 HP와 MP는 새 최대치까지 완전히 회복한다.
- 첫 퀘스트 완료 ID `adventureStart`는 `completedQuests`에 한 번만 기록한다.
- 동일한 적 사망 또는 퀘스트 보고로 보상을 중복 지급하지 않는다.

## 데이터 모델

저장 데이터 v2는 다음 구조를 사용한다.

```js
{
  version: 2,
  level: 1,
  exp: 24,
  nextLevelExp: 100,
  gold: 33,
  completedQuests: ["adventureStart"],
  quests: {
    adventureStart: {
      status: "completed",
      progress: 3
    }
  }
}
```

`exp`는 누적 총 EXP가 아니라 현재 레벨에서 다음 레벨을 향해 쌓인 EXP다. `nextLevelExp`는 저장하고 검증하되 항상 `level * 100`과 일치해야 한다.

최대 능력치는 별도로 저장하지 않고 레벨에서 계산한다.

```js
maxHp = 100 + (level - 1) * 10;
maxMp = 100 + (level - 1) * 5;
```

이를 통해 저장 레벨과 최대 능력치가 불일치하는 상태를 방지한다.

## 코드 구조

### `src/player-progression.js`

성장 계산을 담당하는 순수 모듈이다.

- 레벨별 필요 EXP 계산
- EXP와 Gold 지급
- 초과 EXP 이월과 연속 레벨업
- 슬라임 Gold `1~3` 추첨
- 보상 결과와 레벨업 횟수 반환

무작위 Gold 계산은 테스트에서 고정된 난수를 주입할 수 있게 구성한다. 실제 게임에서는 `Math.random`을 사용한다.

### `src/quest-state.js`

퀘스트 상태와 퀘스트 보상을 담당한다.

- 기존 수락, 처치 진행, 보고 가능, 완료 전이를 유지한다.
- 첫 완료 보고에만 `15 EXP + 30 Gold`를 지급한다.
- 완료 시 `completedQuests`에 `adventureStart`를 중복 없이 추가한다.
- 완료 상태에서 다시 보고해도 데이터와 보상이 증가하지 않는다.

### `src/progress-storage.js`

저장, 검증, 이전을 담당한다.

- v2 저장 키: `pixel-world.progress.v2:<정규화·인코딩된 닉네임>`
- v1 저장 키: `pixel-world.progress.v1:<정규화·인코딩된 닉네임>`
- v2 데이터의 정수 범위, 레벨/필요 EXP 관계, 퀘스트 상태 조합을 검증한다.
- v2가 없거나 손상됐을 때 정상 v1을 v2로 변환한다.
- 변환한 데이터는 v2 키에 저장하되 v1 원본은 삭제하지 않는다.

### `src/game.js`

전투, 퀘스트, 성장, HUD, 저장을 연결한다.

- 적 사망이 확정된 시점에 슬라임 보상을 한 번 지급한다.
- 보상 후 레벨업 결과를 플레이어 능력치에 반영한다.
- 한 레벨 이상 올랐다면 HP와 MP를 새 최대치까지 회복한다.
- 보상과 퀘스트 상태 변경 후 HUD를 갱신하고 즉시 저장한다.
- 부활 시 현재 레벨에서 계산한 최대 HP와 MP를 사용한다.

## 데이터 흐름

### 슬라임 처치

1. 적 사망을 확정한다.
2. 첫 퀘스트가 진행 중이면 처치 진행도를 반영한다.
3. `3 EXP`와 무작위 `1~3 Gold`를 지급한다.
4. EXP를 소비하면서 가능한 모든 레벨업을 처리한다.
5. 레벨업했다면 최대 HP와 MP를 다시 계산하고 완전히 회복한다.
6. HUD와 알림을 갱신한다.
7. v2 진행 데이터를 즉시 저장한다.

### 첫 퀘스트 완료 보고

1. 퀘스트가 `ready_to_report`인지 확인한다.
2. 상태를 `completed`로 변경한다.
3. `completedQuests`에 `adventureStart`를 추가한다.
4. `15 EXP`와 `30 Gold`를 지급한다.
5. 레벨업과 회복을 처리한다.
6. HUD와 알림을 갱신하고 v2 진행 데이터를 저장한다.

첫 퀘스트 전체를 새 데이터로 시작하면 슬라임 세 마리와 완료 보고를 통해 총 `24 EXP`, `33~39 Gold`를 획득한다.

## HUD

플레이어 패널은 다음 값을 표시한다.

- 이름 아래 `LV. {level} · {현재 지역}`
- EXP 텍스트 `{exp} / {nextLevelExp}`
- 현재 레벨 진행률을 나타내는 EXP 막대
- Gold 텍스트 `{gold} G`

알림 문구는 다음 원칙을 사용한다.

- 처치: `슬라임 처치! EXP +3 · Gold +{gold}`
- 레벨업: `LEVEL UP! LV.{level} · HP와 MP가 회복되었습니다.`
- 퀘스트 완료: `퀘스트 완료! EXP 15 · Gold 30을 획득했습니다.`
- 완료 퀘스트 HUD: `완료 · EXP 15 · Gold 30 획득`

## v1에서 v2로 이전

로드 순서는 다음과 같다.

1. 정상 v2 데이터가 있으면 사용한다.
2. v2가 없거나 손상됐다면 정상 v1 데이터를 찾는다.
3. 정상 v1의 EXP와 퀘스트 상태를 보존해 v2로 변환한다.
4. 변환 결과를 v2 키에 저장하고 사용한다.
5. v1도 사용할 수 없으면 신규 v2 데이터를 생성한다.

v1 변환 기본값은 다음과 같다.

- `level: 1`
- `exp: 기존 exp`
- `nextLevelExp: 100`
- `gold: 0`
- 완료 퀘스트이면 `completedQuests: ["adventureStart"]`
- 미완료 퀘스트이면 `completedQuests: []`

현재 v1에서 가능한 EXP는 첫 퀘스트 보상 `15`이므로 변환 시 즉시 레벨업할 데이터는 없다. 이전 로직은 일반적인 유효 EXP도 안전하게 레벨 규칙에 맞춰 정규화할 수 있어야 한다.

## 오류 처리

- v2 JSON 파싱 또는 검증이 실패하면 정상 v1 이전을 시도한다.
- v2와 v1을 모두 사용할 수 없으면 초기 진행 데이터를 반환한다.
- `level`, `exp`, `nextLevelExp`, `gold`는 음수가 아닌 안전한 정수여야 한다.
- `level`은 `1` 이상이고 `exp`는 `nextLevelExp`보다 작아야 한다.
- `nextLevelExp`는 반드시 `level * 100`이어야 한다.
- `completedQuests`는 중복 없는 알려진 퀘스트 ID 배열이어야 한다.
- 퀘스트 상태와 처치 진행도는 도달 가능한 조합만 허용한다.
- localStorage 접근이나 쓰기가 실패해도 게임은 계속 실행하고 저장 실패 안내를 표시한다.

## 테스트 기준

자동 테스트는 다음을 검증한다.

- `nextLevelExp = level * 100`
- 초과 EXP 이월과 한 번의 다중 레벨업
- 레벨업 횟수 및 최종 레벨·EXP
- 레벨업 시 최대 HP `+10`, 최대 MP `+5`, 완전 회복
- 슬라임 처치당 `3 EXP + 1~3 Gold`
- 무작위 Gold의 최솟값, 중간값, 최댓값
- 첫 퀘스트 완료 보상 `15 EXP + 30 Gold`
- 전투 및 퀘스트 보상 중복 지급 방지
- `completedQuests` 중복 등록 방지
- 닉네임별 v2 저장 분리
- 정상 v1에서 v2로 이전
- 손상된 v2에서 정상 v1로 복구
- 잘못된 레벨, EXP, Gold, 완료 퀘스트, 퀘스트 상태 거부
- HUD 필수 요소와 보상 문구
- 기존 전투, 퀘스트, 채팅, 포탈 테스트 회귀 없음

GitHub Pages 배포 후에는 슬라임 처치 보상, 퀘스트 보고 보상, 레벨 HUD, 나가기와 동일 닉네임 재입장 후 진행 복원을 점검한다.
